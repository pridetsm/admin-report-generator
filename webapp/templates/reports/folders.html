How to read this

How long the oldest file has been waiting in each watched folder. A folder that stops draining is a consumer that has stopped running.

Each folder is coloured by whether any file in it has been waiting past the age limit set on the host. The host applies that limit itself and publishes the result — how many files are over it — so this page holds no thresholds of its own and retuning one is an edit on the server alone.

Grey is healthy. An empty interface folder means everything drained, which is the normal steady state. Green means files are waiting and none of them is over the limit — work in progress. Red means a file has been sitting past the limit: the folder is not busy, it is jammed, and the consumer that should be draining it has almost certainly stopped. There is no amber band, because the host publishes only the one threshold — there is no second, earlier line to warn against.

Dashed and faded is neither good nor bad — it means we are not being told. Either the path could not be found on the host, the run reported an error, or the check itself has not run recently. The textfile the host publishes is re-served unchanged until it is rewritten, so a dead check would otherwise read as a permanently perfect folder. It is called out rather than coloured in.

Two clocks, and they mean different things. live, by the toolbar heartbeat, is this page still reaching the server. Last checked, at the top of the page, is the host still looking at the folders — it counts up on its own and turns red once it passes {{ fw.stale_after }} seconds. The page can be perfectly live while the readings behind it are hours old, so that top figure is the one that says whether any of this is current.

The host measures each file's age at the moment it runs, and that number is frozen until the next run. This page subtracts it from the run's own timestamp to recover when the file actually arrived, then ages it from there once a second — so a folder crosses into red the moment it truly does, not at the next check.
