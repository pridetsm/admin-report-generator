These fields are {{ yaml_source.path }}, shown one setting at a time. It is the same file and the same history as Prometheus (raw) — saving here records a revision there, and vice versa. Filling in labelled fields instead of editing YAML by hand is what keeps indentation, quoting and duration syntax from breaking the config.

Save records a revision and changes nothing live. Save & Apply runs the real promtool check config first and only rewrites prometheus.yml and restarts the service if it passes — a broken edit never reaches the live file. Values this form doesn’t model (params, relabel_configs, …) are preserved untouched and shown read-only.

One caveat: saving through this form drops the comments inside the file body (the header block is kept). prometheus.yml carries a lot of hand-written rationale — if you need to keep it, edit the raw text instead. Either way the previous revision stays in the history below.
